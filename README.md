# MorseWatch — декодер морзянки на слух для Galaxy Watch (Wear OS) и телефона

Краткая инструкция по обоим приложениям — в [DOCS.md](DOCS.md).

Слушает микрофон часов и в реальном времени выводит символы на экран. Тон и скорость не задаются: они
определяются из сигнала и подстраиваются по ходу.

```
morse-core/   чистый Kotlin (без Android) — весь декодер. Проверен на JVM на ваших записях.
app/          приложение для часов (Wear OS): захват звука, незаметный экран.
phone/        приложение для телефона (Android 8+): тот же декодер, обычный экран с полным текстом.
prototype/    Python-эталон того же алгоритма (для экспериментов и сверки).
```

## Как работает ядро
1. **Тон**: банк фильтров Гёрцеля 300–1200 Гц, пик на 12+ дБ выше шума → несущая; следит за дрейфом.
2. **Огибающая**: демодуляция на найденной частоте, кадр 5 мс.
3. **Нажатие/отпускание**: по *наклону* огибающей, а не по порогу. Комната размазывает затухание,
   но не фронт; поэтому порог по уровню на записях со звуком из колонок не работает, а по наклону — работает.
4. **Старт (первые ~14 элементов)**: скорость неизвестна, поэтому отрезки только копятся, затем устойчивая
   подгонка находит длину точки T, помехи чистятся, и буквы раскладываются разом.
5. **Дальше**: точка/тире — кластеризация длин (2-средних, лог-шкала), паузы — кратные T и медиане
   «длинных» пауз. Скорость отслеживается непрерывно.

## Сборка и установка
1. Android Studio (Ladybug или новее) → *Open* → папка проекта → дождаться Gradle Sync.
2. На часах: Настройки → О часах → Данные о ПО → 7 раз нажать «Версия ПО» → Параметры разработчика →
   «Отладка по Wi-Fi». В Android Studio: Device Manager → Pair Devices Using Wi-Fi.
3. Run ▶ `app`. При первом запуске — разрешить микрофон. ▶ на экране начинает слушать, ■ останавливает.

Экран в «незаметном» режиме: чёрный фон и один маленький тусклый символ у края со стороны физических кнопок (константа `BUTTONS_ON_RIGHT` в `MorseScreen.kt`). Тап по экрану — слушать/стоп, долгое нажатие — RU/EN. `·` — слушает, но символов ещё нет; `!` — ошибка (например, нет доступа к микрофону).

> ВНИМАНИЕ: Android-часть (`app/`) в момент передачи **не собиралась и не запускалась** — в среде, где она
> писалась, нет Android SDK и доступа к Google Maven. Версии библиотек выбраны консервативно (AGP 8.7.3,
> Kotlin 2.0.21, Wear Compose 1.4.1); если Studio предложит обновить — обновляйте. Ядро `morse-core`
> компилировалось и тестировалось отдельно.

## Проверка ядра на ПК
```bash
ffmpeg -i запись.m4a -ac 1 -ar 16000 -c:a pcm_s16le запись.wav
./gradlew :morse-core:run --args="запись.wav ru"      # или en
```
Синтетическая самопроверка без аудиофайлов: запустить `morse.cli.SelfTestKt` (из IDE).

## Известные ограничения
* Первые 1–3 символа после старта и после резкой смены скорости могут быть неверными (идёт калибровка).
* Рабочий диапазон на ваших записях: тон 360–1140 Гц, скорость ~3–24 WPM, шум до 0 дБ SNR.
  На ~28 WPM в реверберирующей комнате паузы между элементами стираются — предел для такого звука.
  Быстрый (≥20 WPM) чистый сигнал с шумом ≈10 дБ тоже может давать ошибки в середине текста.
* Одиночное «плечо» (провал уровня на ~8 дБ посреди длинного тире из-за интерференции в комнате) читается
  как два элемента; такой символ покажется как `?`.
* Без foreground-сервиса: слушает, пока приложение на экране (экран не гаснет). При сворачивании запись
  останавливается.
* Пунктуация по умолчанию выключена (`MorseTables.build(alphabet, punctuation = true)`).

## Что подкрутить
Все пороги — в начале `KeyDecoder.kt` (`slopeUp/Down`, `onLevelDb`, `minSnrDb`, `bootOnRuns`).
Следующие шаги: foreground-сервис с типом `microphone` (слушать при погашенном экране), виброотклик на
символ, режим «показывать сырой код», коррекция ошибок по словарю.
